<Note>

</Note>

The **Trigger** feature exposes **Autonomous Agent Graphs** as callable **API endpoints**. External systems (monitoring, backends, webhooks) invoke triggers over HTTP to start configured graph runs.

Unlike conversational channels, autonomous triggers support three **execution modes**:

1. **API (Single Endpoint)** — synchronous execution for simple flows (≤ ~120–150 seconds). Not recommended for complex graphs.
2. **Background Task** — asynchronous `/start` + `/status` endpoints (≤ 45 minutes). **Recommended for most use cases.**
3. **Cron Job** — schedule runs on the platform; no external caller after setup.

## Enable a trigger as an API

1. Open the **Edit Trigger** modal in **Integrations** → **Triggers**.
2. Select **workflow type** — API, Background Task, or Cron Job.
3. Select an **Integration** from the **Integration Funnel** when applicable ([Jira funnel](/triggers-intents/triggers/integration-funnel)).
4. Select the **Agent Graph** / flow to run and assign an **Agent Build**.
5. Save the trigger configuration.
6. Create or update the **Agent Build** if the graph changed ([Builds overview](/builds/overview)).

Once enabled, the platform generates **API URLs** for **DEV**, **UAT**, and **PROD**.

## Authentication

All API requests must include a valid **Bearer Token** in the `Authorization` header. The API key is configured at the workspace level.

```bash
Authorization: Bearer <YOUR_WORKSPACE_API_KEY>
```

Requests without a valid token are rejected.

<Tip>
  Test authentication in **DEV** before promoting trigger build assignments to **PROD**.
</Tip>
