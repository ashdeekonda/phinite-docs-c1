---
title: "Execution Mode 2: Background Task (Recommended)"
description: Asynchronous trigger API with start and status endpoints for Autonomous Agent Graphs.
---

<Note>
  **Background task** mode is the recommended way to run multi-step **Autonomous Agent Graphs** (up to **45 minutes**). Assign the correct **Agent Build** per environment before calling `/start`.
</Note>

### Overview

Background task mode provides **asynchronous execution** with two endpoints: one to start the graph run and another to check status.

**Benefits:**

- Maximum execution time: **2700 seconds (45 minutes)**
- Suitable for complex, multi-step Agent Graphs
- Real-time progress tracking through logs
- Non-blocking API calls

### Step 1: Start the Agent Graph

#### Endpoint

```text
POST https://app.phinite.ai/api/v1/ai/trigger/start/{workspace_id}/{trigger_id}/{environment}
```

#### Request payload

```json
{
  "message": "start the task",
  "user_variables": {
    "key1": "value1",
    "key2": "value2"
  }
}
```

#### Initial response

```json
{
  "workflow_id": "workflowid-uuid",
  "response": {},
  "status": "pending",
  "logs": [],
  "requires_input": false,
  "error": null
}
```

The `workflow_id` returned in this response tracks execution status.

### Step 2: Check status

#### Endpoint

```text
GET https://ai-core.phinite.ai/trigger/status/{workspace_id}/{workflow_id}
```

The status endpoint returns one of three statuses with HTTP 200:

- `pending` — Agent Graph is still executing
- `completed` — Agent Graph finished successfully
- `failed` — Agent Graph encountered an error

#### Status response: Pending

While the graph runs, the status endpoint returns recent logs:

```json
{
  "workflow_id": "workflowid-uuid",
  "response": {},
  "status": "pending",
  "logs": [
    {
      "time": "2026-02-09 23:24:39",
      "level": "tool_call",
      "node_id": "Agent 1",
      "message": "Tool Invoked with parameters",
      "status": "running",
      "user_logs_type": ""
    }
  ],
  "requires_input": false,
  "error": null
}
```

<Note>
  The `logs` array provides recent execution progress — typically the last 4–5 entries, not the full log history.
</Note>

#### Status response: Completed

When the graph finishes successfully:

```json
{
  "workflow_id": "workflowid-uuid",
  "response": {
    "workflow_id": "workflowid-uuid",
    "key1": "value1",
    "key2": "value2"
  },
  "status": "completed",
  "logs": [...],
  "requires_input": false,
  "error": null
}
```

The `response` object contains the workflow ID and session variables set during execution.

#### Status response: Failed

```json
{
  "workflow_id": "workflowid-uuid",
  "response": {},
  "status": "failed",
  "logs": [...],
  "requires_input": false,
  "error": "Detailed error message"
}
```
